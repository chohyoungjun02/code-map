# Code Map

AI로 만든 코드의 구조를 한눈에 보여 주는 웹 서비스입니다.

**배포 링크**: https://code-map-delta.vercel.app

## 왜 만들었나
AI로 코드를 짜면 어느 파일이 어떤 역할을 하는지 알기 어렵습니다. 그래서 오류를 AI에게 고쳐 달라고 할 때도 전체 코드를 통째로 보내게 되고, 토큰이 낭비됩니다.
Code Map은 코드 구조를 그래프로 보여 주고 오류가 나기 쉬운 곳을 표시합니다. 그래서 어디를 고쳐야 할지 먼저 파악하고, 필요한 파일만 골라 AI에게 요청할 수 있습니다.

## 주요 기능

### 1. 의존성 그래프
- 프로젝트 폴더를 열면 파일끼리 누가 누구를 import 하는지 화살표로 보여 줍니다.
- 지원 언어:
  - **JS/TS(React)**: `@/` 같은 tsconfig 경로 별칭 포함
  - **Python**: 상대 import, `src/` 아래 패키지
  - **Java**: 같은 패키지 클래스 참조, `*` import, static import
- 폴더별로 상자를 묶어 볼 수 있고, 다른 파일과 연결이 없는 파일은 아래에 따로 모읍니다.
- 진입점(`main`, 라우트 파일, 테스트, `__main__`, Spring 컨트롤러 등)을 구분해서 표시합니다.

### 2. 유지보수 위험 표시
AI 없이 그래프만으로 계산합니다.
- **영향 범위 큼**: 직접·간접으로 의존하는 파일이 많은 파일
- **순환 의존**: 서로가 서로를 import 하는 파일
- **큰 파일**: 300줄이 넘는 파일
- **사용 안 됨 / 안 쓰는 export**

### 3. git 커밋 비교
`.git`이 있는 폴더를 열면, 두 커밋(또는 커밋과 지금 폴더)을 골라 비교합니다. 새 파일, 바뀐 파일, 삭제된 파일, 새로 생긴 연결, 이번 변경으로 새로 생긴 위험을 보여 줍니다. 바뀐 파일은 줄 단위 차이도 볼 수 있습니다.

### 4. React 컴포넌트 트리
React 프로젝트에서는 어떤 컴포넌트가 어떤 컴포넌트를 화면에 그리는지 부모→자식 트리로 보여 줍니다.

### 5. AI 설명 (Google Gemini)
- **폴더 역할 설명받기**: 폴더마다 맡은 역할을 한 문장으로 설명합니다.
- **파일 역할 설명받기**: 모든 파일의 역할을 한 번에 받아 목록, 파일 상세 패널, 그래프 상자 말풍선에 보여 줍니다.
- **변경 내용 한 줄 요약**: 커밋 비교 중일 때 무엇이 바뀌었는지 요약합니다.

### 6. AI 수정 요청 프롬프트
오류 메시지나 스택 트레이스를 붙여 넣으면 그 안에 나온 프로젝트 파일을 찾아 줍니다(오류가 난 곳에 가까운 순서). 파일을 누르면 오류가 미리 적혀 있고, 스택 트레이스에 함께 나온 파일이 체크된 프롬프트가 열립니다.

파일을 선택하고 오류 메시지를 적은 뒤 함께 보낼 파일을 고르면, 수정 요청 프롬프트를 만들어 복사해 줍니다. 같이 보낼 수 있는 파일은 그 파일이 import 하는 파일과 그 파일을 import 하는 파일입니다.
프롬프트에는 Code Map의 분석 결과(연결된 파일, 위험 경고)가 함께 들어갑니다. 전체 코드를 보낼 때와 비교한 토큰 절약량도 보여 줍니다. 예제 프로젝트에서는 약 63%를 절약했습니다.

## 기술 스택
| 구분 | 사용 기술 |
|---|---|
| 프론트엔드 | React 19, Vite |
| 그래프 | @xyflow/react (React Flow), @dagrejs/dagre (자동 배치) |
| 코드 분석 | @babel/parser (JS/TS), 정규식 기반 분석 (Python, Java) |
| git | isomorphic-git (브라우저에서 `.git` 읽기) |
| AI | Google Gemini API (`gemini-3.5-flash-lite`) |
| 배포 | Vercel (정적 사이트 + 서버리스 함수) |

## 동작 방식
- **코드 분석은 브라우저 안에서만** 합니다. 폴더를 열어도 코드가 서버로 가지 않습니다.
- AI 버튼을 누를 때만 코드 일부가 서버를 거쳐 Gemini로 갑니다. 큰 프로젝트는 파일마다 앞부분만 보냅니다.
- **API 키는 서버에만** 있습니다. 브라우저는 `/api/gemini`로 요청하고, 서버가 키를 붙여 Google에 전달합니다. 개발 중에는 Vite 서버(`server/gemini-proxy.js`)가, 배포 환경에서는 Vercel 함수(`api/gemini.js`)가 이 일을 합니다.
- Gemini가 붐벼서 503으로 답하면 3초 뒤 한 번 자동으로 다시 시도하고, 60초 안에 답이 없으면 안내를 띄웁니다.

## 폴더 구조
```
api/gemini.js          Vercel 서버리스 함수 (AI 요청 중계)
server/gemini-proxy.js AI 요청 중계 (API 키 추가, 모델 고정, 시간 제한)
src/
  App.jsx              화면 전체 (그래프, 패널, 커밋 비교, AI 버튼)
  analyze.js           코드 분석: import 추출, 경로 해석, 순환 의존, 위험, 컴포넌트 트리, 배치
  diff.js              두 버전 비교, 줄 단위 차이
  git.js               브라우저에서 커밋 목록과 커밋별 파일 읽기
  ai.js                Gemini 요청 (폴더·파일 역할, 변경 요약)
  prompt.js            AI 수정 요청 프롬프트 생성, 토큰 어림 계산
  demo.js              "예제: 이 앱 자체 보기" 데이터
  *.test.js            단위 테스트
```

## 실행 방법
```bash
npm install
cp .env.example .env.local   # GEMINI_API_KEY 입력 (AI 기능용, 없어도 나머지 기능은 동작)
npm run dev
```
배포할 때는 Vercel 프로젝트의 환경 변수에 `GEMINI_API_KEY`를 설정하세요.

## 테스트
```bash
node src/analyze.test.js && node src/ai.test.js && node src/prompt.test.js
```
AI 테스트는 Google 호출을 가짜 응답으로 바꿔서 실행하므로 키 없이 돌아갑니다.

## 한계
- Python, Java는 정규식으로 분석합니다. 그래서 문자열 안의 `import` 문장도 import로 셀 수 있고, 자바 같은 패키지 연결은 클래스 이름으로 찾기 때문에 이름이 우연히 같으면 잘못 연결될 수 있습니다.
- 컴포넌트 트리는 `index.js`를 거친 재수출(re-export)을 따라가지 않습니다.
- 토큰 수는 어림값입니다(영문 4글자 ≈ 1토큰, 한글 1글자 ≈ 1토큰).
- 무료 Gemini 등급을 쓰므로, 보낸 코드가 Google의 서비스 개선에 사용될 수 있습니다. 민감한 코드에는 AI 기능을 쓰지 마세요.
